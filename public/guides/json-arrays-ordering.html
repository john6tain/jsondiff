JSON arrays and ordering: what a diff can and can't tell you

Updated August 3, 2026 ~4 min read

Arrays are ordered, objects are not — and that single fact drives most of the surprising results people get from JSON diff tools.

An array is an ordered list

Unlike an object's keys, an array's positions are part of the data. [1, 2, 3] and [3, 2, 1] are different documents because 1 lives at a different index in each. This is by design: arrays model lists — queues, leaderboards, logs, hosts in a load balancer — where position carries meaning.

How the diff reports array changes

Because position matters, a structural diff compares arrays element by element, by index:

  • An element at index i on the right that isn't there on the left is added at arr[i].
  • The reverse is removed.
  • An element that changed in place is edited.

The consequence: reordering is reported as removes and adds, never as "moves." The tool doesn't try to guess which element moved where — it tells you what happened at each index, which is unambiguous and easy to reason about.

Worked example: a reordered priority list

The set of tasks is identical — but "send-receipts" is now the highest priority. A diff that ignored order would report "no changes" and you'd miss a scheduling change that reorders real work. A diff that respects order flags index 0 and index 1. Which one you want depends entirely on what the array means.

Reordering vs set membership

The question to ask before comparing is: does order carry meaning here?

  • Order means something (priority queue, sorted leaderboard, playback sequence): the reorder is the change. Report it, review it, keep it.
  • Order is incidental (a bag of tags, a set of unique IDs): the reorder is noise. Sort both arrays before comparing, and only real differences — added or removed elements — will survive.

There's a reason the tool doesn't auto-sort: it can't know which case you're in. Forcing sorted comparison would silently destroy exactly the signal someone debugging a priority change is looking for.

What the diff can't tell you

A diff reports index-level changes; it does not tell you why an array changed. If an element is removed and a new one added, that could be a rename (same item, new string), a swap (two items exchanged), or a genuine replacement (one item deleted, a different one inserted). The change list gives you the before/after values at each index — the interpretation is up to you, and usually obvious from the values themselves.

Practical rules

  • Diff arrays by index unless you have a reason not to.
  • If you don't care about order, sort first — deterministically, on both sides.
  • If you care only about membership (is this value present or not), compare sets instead, and treat reorder output as expected noise.
