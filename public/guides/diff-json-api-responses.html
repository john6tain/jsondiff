How to diff JSON API responses when debugging a broken integration

Updated August 3, 2026 ~5 min read

Your client worked yesterday. Today it throws. Somewhere in the response the API changed — a renamed key, a changed type, a field that moved. Here's how to find the exact field in a few minutes instead of an afternoon.

Start with the two responses

You need a reliable "before". Good sources, in order of preference:

  • A recorded response from the last time it worked (a test fixture, a saved log line, an integration test snapshot).
  • The response shape from an older commit or release of your code.
  • The API's own documentation or OpenAPI schema, if it's kept current.

Put the known-good response on the left and the current response on the right of the diff tool. Paste them as raw JSON — the tool parses and pretty-prints both sides itself, so you don't need to reformat by hand.

Read the three kinds of change

Whatever diff tool you use, it's reporting three things:

  • Added — a key that wasn't there before. Your code may simply ignore it, or it may mask a change you actually care about.
  • Removed — a key your code depended on. This is usually the breakage: response.user.name becomes undefined, and the next line that calls .toUpperCase() on it throws.
  • Edited — the key is still there but the value (or its type) changed.

On a large payload, switch to the change list view: it renders one row per change with the full path (like user.contact.email) and the old and new values, which is the fastest thing to scan when the response has dozens of fields.

The changes that break clients, ranked

ChangeWhat it does to your code
Field removedProperty access returns undefined; downstream calls throw.
Type changed"price" string becomes a number: concatenation and comparison behave differently.
Field renamedSame data, new key — your code reads the old key and gets undefined.
Field moved into a nested objectThe value is still there, but the path changed, so the lookup fails.
Array reordered or reindexedIndex-based access reads a different element than intended.

When the diff shows nothing

If the two payloads are byte-identical and your code still fails, the problem isn't the response body. Look at headers, status codes, pagination links, or an envelope field you stripped out before comparing. A "no differences" result is still a useful negative result: it tells you where not to keep digging.
