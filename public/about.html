About JSON Diff

What it is

JSON Diff is a free, browser-based tool for comparing two JSON documents. It shows added, removed, and edited fields, highlights the exact characters that changed inside a modified line, and offers a structured change list for reporting. Everything runs in your browser — the split view aligns lines locally, and the change list uses the same diff engine bundled into the page, so your payloads never leave your device.

Why it exists

The tool started the way most small tools do: with a specific, recurring annoyance. While debugging API integrations, the pattern was always the same — a client that worked yesterday throws today, and somewhere in a multi-hundred-line response a single field changed. Existing diff tools were either slow, uploaded the data to a server, or produced noisy line-level diffs that buried the one real change under formatting differences.

So this tool was built to do three things the author kept wanting:

  • Run locally. JSON payloads are often sensitive — API keys, PII, internal config. Nothing should be uploaded to compare two documents.
  • Highlight the exact change. Not just "this line is different," but the precise characters inside the line.
  • Tell the structural story. A change list that says deploy.instances: 2 → 4 instead of a wall of red and green.

Who maintains it

JSON Diff is an open-source side project maintained by John6tain. The source is on GitHub under the GPL-3.0 license, and contributions — bug reports, feature ideas, pull requests — are welcome. It's free to use, has no accounts, and there are no plans to change that.

How it works under the hood

The frontend is plain HTML, CSS, and JavaScript — no framework, nothing to build. The split view uses a dynamic-programming alignment (longest common subsequence) to pair up lines, then a character-level pass to find the exact changed text inside each modified pair. The change list uses deep-diff, a small structural-diff library, bundled directly into the page. It's deployed on Vercel, and there's also a tiny POST /api/diff endpoint for scripts that want structured output (the web UI itself never calls it).

The design decisions

  • Key order never counts as a difference — JSON objects are unordered.
  • Types are never coerced — "1" vs 1 is reported as an edit, not ignored.
  • Arrays are compared by index — reordering is a real change, because it can be.
  • No ads on the tool itself — the comparison interface stays clean; ads, when present, only appear alongside the written content on this site.

If any of those decisions doesn't match how you think about JSON, the guides explain the reasoning in more depth.
